## Phase 6 Tasks

### 6.1 Code Review Fact-Checking Protocol

**Objective**: Verify all AI-generated code against validation gates.

**Steps**:
1. Identify all AI-generated code changes:
   ```bash
   # Find recently modified files
   git diff --name-only HEAD~10

   # Check for AI-generated markers (if any)
   grep -r "Generated by\|AI-generated\|@generated" . --include="*.ts"
   ```

2. Run validation gates on each file:
   ```bash
   # Type checking
   npx tsc --noEmit

   # Linting
   npx eslint src/ --format json

   # Security scan
   npx audit-ci --critical

   # Tests
   yarn test --coverage
   ```

3. Create fact-check report:
   ```markdown
   ## Code Validation Report

   | File | Types | Lint | Security | Tests | Status |
   |------|-------|------|----------|-------|--------|
   | src/action.ts | PASS | PASS | PASS | PASS | VERIFIED |
   | src/utils.ts | PASS | 2 warn | PASS | PASS | REVIEW |
   ```

4. **Verification Loop**:
   - For each warning/error, verify it's valid
   - Check if issues existed before AI changes
   - Document resolution for each issue

**Output**: Create `.claude/validation/code-review-report.md`

### 6.2 Documentation Accuracy Validation

**Objective**: Verify all documentation claims against actual code.

**Steps**:
1. Extract claims from documentation:
   ```bash
   # Find all code references in docs
   grep -r "src/\|\.ts:\|\.js:" docs/ --include="*.md"

   # Find version claims
   grep -r "version\|v[0-9]" docs/ --include="*.md"

   # Find feature claims
   grep -r "supports\|provides\|includes" docs/ --include="*.md"
   ```

2. Validate each claim type:

   **File References**:
   ```bash
   # For each file:line reference, verify it exists
   # docs says "src/utils.ts:45" has function X
   sed -n '45p' src/utils.ts  # Verify content
   ```

   **Version Claims**:
   ```bash
   # Verify against package.json
   cat package.json | jq '.version'
   cat package.json | jq '.dependencies'
   ```

   **Feature Claims**:
   ```bash
   # Search for feature implementation
   grep -r "featureName" src/ --include="*.ts"
   ```

3. Create accuracy report:
   ```markdown
   ## Documentation Accuracy Report

   | Document | Claims | Verified | Issues |
   |----------|--------|----------|--------|
   | README.md | 15 | 14 | 1 outdated version |
   | ARCHITECTURE.md | 23 | 23 | None |
   ```

4. **Verification Loop**:
   - Cross-reference each claim with code
   - Test documented examples
   - Verify commands work as documented

**Output**: Create `.claude/validation/documentation-accuracy-report.md`

### 6.3 Chain-of-Verification (CoVe) Implementation

**Objective**: Apply systematic verification to all claims.

**Steps**:
1. For each major output, apply CoVe:
   ```markdown
   ## CoVe Protocol for [Document]

   ### Initial Claim
   "[The system uses Redis for caching with 1-hour TTL]"

   ### Verification Questions
   Q1: Does the codebase reference Redis?
   Q2: Where is the TTL configured?
   Q3: Is 1 hour the actual value?
   Q4: Are there exceptions to this TTL?

   ### Verification Answers
   A1: grep -r "redis" src/ → [result]
   A2: cat src/config/cache.ts:15-20 → [result]
   A3: TTL = 3600 seconds = 1 hour ✓
   A4: Session cache uses 300s, not 3600s ✗

   ### Verified Claim
   "[The system uses Redis for caching with variable TTL:
   - Default: 1 hour (3600s)
   - Sessions: 5 minutes (300s)]"
   ```

2. Document CoVe process for future use:
   - Template for verification
   - Question patterns by claim type
   - Evidence collection standards

3. **Verification Loop**:
   - Apply CoVe to at least 10 major claims
   - Document correction rate
   - Identify common hallucination patterns

**Output**: Create `.claude/validation/cove-verification-log.md`

### 6.4 Hallucination Detection Checklist

**Objective**: Create systematic hallucination detection.

**Steps**:
1. Define hallucination patterns to check:
   ```markdown
   ## Hallucination Checklist

   ### Dependency Claims
   - [ ] All mentioned packages exist in package.json
   - [ ] Versions match lock file
   - [ ] No phantom dependencies

   ### API Claims
   - [ ] Functions exist with stated signatures
   - [ ] Parameters match actual code
   - [ ] Return types are accurate

   ### Configuration Claims
   - [ ] Config files exist
   - [ ] Values match actual settings
   - [ ] Paths are correct

   ### Performance Claims
   - [ ] Benchmarks were actually run
   - [ ] Numbers match test results
   - [ ] Methodology documented
   ```

2. Run checklist on all outputs:
   ```bash
   # Dependency verification
   for pkg in $(grep -o '"[^"]*":' package.json | tr -d '":'); do
     if ! grep -q "$pkg" yarn.lock; then
       echo "HALLUCINATION: $pkg not in lock file"
     fi
   done
   ```

3. Create detection report:
   ```markdown
   ## Hallucination Detection Report

   | Category | Checked | Hallucinations | Accuracy |
   |----------|---------|----------------|----------|
   | Dependencies | 45 | 2 | 95.6% |
   | APIs | 23 | 1 | 95.7% |
   | Configs | 12 | 0 | 100% |
   ```

4. **Verification Loop**:
   - Run checklist on each agent's outputs
   - Document all detected hallucinations
   - Track hallucination rate over time

**Output**: Create `.claude/validation/hallucination-detection-report.md`

### 6.5 Automated Review Pipeline

**Objective**: Automate validation for continuous review.

**Steps**:
1. Create validation script:
   ```bash
   #!/bin/bash
   # scripts/validate-ai-outputs.sh

   echo "=== AI Output Validation ==="

   # Check code
   echo "Checking types..."
   npx tsc --noEmit || exit 1

   echo "Checking lint..."
   npx eslint src/ || exit 1

   echo "Running tests..."
   yarn test || exit 1

   # Check documentation
   echo "Validating doc references..."
   ./scripts/check-doc-refs.sh || exit 1

   echo "=== All validations passed ==="
   ```

2. Integrate with CI:
   ```yaml
   - name: Validate AI Outputs
     run: ./scripts/validate-ai-outputs.sh
   ```

3. Create feedback loop:
   - Log all validation failures
   - Track patterns in failures
   - Update prompts to prevent recurrence

4. **Verification Loop**:
   - Test pipeline catches known issues
   - Verify pipeline doesn't false-positive
   - Document edge cases

**Output**: Create `scripts/validate-ai-outputs.sh` and `.claude/validation/validation-pipeline.md`
